# レビュー観点: 表現・表記

誤字・表記・文の読みやすさと、提出先の書式を確認する。論理構成の評価は対象外。

## 基本
- 誤字・脱字・変換ミス、文法・語法の誤り（助詞の誤用、係り受けのねじれ）
  例：✕「結果を示めす」→ ○「結果を示す」
- 同じ概念に複数の表記が混ざっていないか
  例：✕「ユーザ」と「ユーザー」が混在 → どちらかに統一する
- 一文が長すぎないか。LaTeX のコマンドと表示内容が合っているか

## 句読点
- 「、。」と「，．」が混ざっていないか（文書の中でどちらかに統一する）
- 文末の句点が抜けていないか
  例：✕ 箇条書き以外の文で「〜を示す」で終わっている → ○ 文書で使っている句点を付ける
- 中黒（・）で並べたとき、前後の語がつながって読めてしまう場合は読点にする
  例：✕「理論・実験結果」→ ○「理論、実験結果」

## 記号と数値
- 範囲や両端のある尺度には enダッシュ（LaTeX では --）を使う。長音記号（ー）やハイフン1つは使わない
  例：✕「心地よいー心地わるい」→ ○「心地よい--心地わるい」
- 引用符は開きと閉じで記号が違う。LaTeX ではストレートな " ではなく `` と '' を使う
  例：✕ "word" → ○ ``word''
- 同じ種類の数値は桁数をそろえる
  例：✕「-1〜1」→ ○「-1.0〜1.0」

## 文と用語
- 冗長な文末を削る
  例：✕「表示されるものである」→ ○「表示される」
- 条件と重複している語を削る
  例：✕「閾値以下の場合のみ、限定して処理する」→ ○「閾値以下の場合のみ処理する」
- 処理の対象を正確な語で書く
  例：✕「色を変える」（実際は色相だけを変える）→ ○「色相を変える」
- 図表のキャプションは見出しではなく、内容を表す言葉にする
  例：✕「実験1の結果：比較」→ ○「条件ごとの評価値の比較結果」

## 提出先の書式
- 共通の指示で特定した提出先のテンプレートに従っているか（ページ数、必須の項目や章、図表とキャプションの位置、著者情報や概要の体裁など）
  例：✕ テンプレートの見本ではキャプションが図の下、本文では上 → テンプレートに合わせる
- テンプレートの指定を本文側で上書きしていないか（\setlength や \usepackage による余白・フォント・行間の変更など）

## 修正案（suggestion）
直す範囲と内容に迷いがない指摘には、comments の suggestion に修正後のテキストを入れる。筆者は PR 上のボタンひとつでそのまま反映できる。
- 出すのは、誤字、表記揺れ、句読点、短い言い換え、.bib の書誌情報の補完のように、その範囲だけで直せて修正内容に迷いがないときだけ
- 直し方が複数考えられるもの、範囲の外にも影響するもの、書き足す内容を筆者が決める必要があるものには出さない。表記の混在（「。」と「．」など）でどちらに揃えるかが文書から決まらない場合も出さない
- suggestion を出すときは、basis に根拠を必ず書く。basis のない suggestion は投稿時に外される
  - リポジトリ内に根拠があるとき：その場所を書く　例：「main.tex:L345（コメントアウトされた旧参考文献リスト）」
  - 誤字や表記の統一のように、根拠が本文の書き方そのものにあるとき：何を見て決めたかを書く　例：「同じ文書の L20, L48 では『ユーザ』と表記」
  - リポジトリ内に根拠がなく、自分の知識から補うとき（.bib の巻・号・ページなど）：出典（誌名・年・DOI など分かる範囲）を書き、body の最後に「値は出典で確認してから反映してください」と書く
- suggestion は path の start_line〜line（start_line がなければ line だけ）の行をまるごと置き換える。範囲内の行を、LaTeX のコマンドやインデントも含めて正確に全部書く。一部だけ書くと、それ以外の部分が消える
- 範囲は直す行だけに絞る。body には ```suggestion を書かない（投稿時に自動で付ける）
  例：12行目が「\item 結果を示めす．」なら、line: 12、suggestion: 「\item 結果を示す．」（行全体）。suggestion を「示す」だけにすると、12行目全体が「示す」に置き換わってしまう
